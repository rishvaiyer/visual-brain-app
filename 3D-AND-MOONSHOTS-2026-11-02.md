## Go to 3D

**What it should do:** Select one or more image objects on an existing board, click **Go to 3D**, and land on a **new board**. That board keeps the selected pictures beside a separate rotatable 3D object for each selection. It should support rotate, zoom, a still snapshot, and download of the model. Keep the source board untouched. If one object has several photos from different angles, combine those photos into *one* model instead of charging or generating one model per photo. A single photo leaves hidden sides to be guessed; several views of the same object can reduce that guesswork.

**Free-now path:** First support imported `.glb` models on boards and validate the complete selection → new board → model-viewer flow. For *generation*, run a free, open-source model on the Ryzen after a bounded quality and speed test. [TripoSR](https://github.com/VAST-AI-Research/TripoSR) is MIT licensed and its maintainers say CPU inference works; [Stable Fast 3D](https://github.com/Stability-AI/stable-fast-3d) also documents a CPU fallback. Neither has been tested on Rishva's Ryzen for usable speed or result quality. The Ryzen has no GPU and was heavily loaded at this review, so do not promise instant conversion. A browser can display GLB models with [Google's model-viewer](https://modelviewer.dev/docs/) and `camera-controls`.

**Later premium option:** If Rishva eventually chooses to charge, generated models could be a paid feature; the current app stays free. A hosted model API would introduce a per-generation operating cost and would send selected images to that provider. [Meshy's official API](https://docs.meshy.ai/en/api/multi-image-to-3d) accepts one to four photos of the *same object*, returns a model asynchronously, and [charges credits](https://docs.meshy.ai/en/api/pricing). Its [webhooks](https://docs.meshy.ai/en/api/webhooks) can fill finished models into boards without a wait loop. This is an option for a separate future decision, not part of the free-now implementation.

**Existing fit:** The current app already tracks selected canvas items in `app.js`, creates boards through `/api/boards`, and stores original image assets. It has no model asset type, GLB storage/viewer, generation worker, user accounts, or billing. The public playground resets data periodically, so a real model should be stored with the user's local board data and included in backup/restore before declaring this feature complete. Koi One's image-save bridge is separate and does not prove 3D generation.

**Smallest honest test:** On the Ryzen, run the same freely usable object photo through TripoSR and Stable Fast 3D once each, recording wall time, memory, and whether the result looks like a useful object from front, side, and back. If either succeeds at tolerable speed, build the free new-board workflow around it. If neither does, show the rotatable imported-model board while preserving the generation goal as unproven. No paid provider or image transfer should be silently substituted.

## Twelve distinct moonshots

These are opportunities, **not built features**. They cover different jobs a visual collection could do, rather than twelve versions of 3D.

| # | Feature idea | What a person gets |
|---|---|---|
| 1 | **Go to 3D** | Selected object pictures become rotatable models on a new board. |
| 2 | **Walk through a board** | A board becomes an explorable gallery or room; ideas are felt at human scale. This arranges a space rather than making each object into a mesh. |
| 3 | **Place it here** | A 3D object appears at scale in a live view of your room so you can judge fit before making or buying it. |
| 4 | **Point and reopen** | Point a camera at a real object and open the boards where you saved that object or visual match. |
| 5 | **The source trail** | Reconnect an image to its original page, maker, license, and buying or citation path, with uncertainty shown. |
| 6 | **Taste map** | Reveal clusters and unexpected connections among everything saved, then jump to the boards behind a visual theme. |
| 7 | **Three directions** | Branch one selection into distinct design directions while keeping every original image and the history of choices. |
| 8 | **Board to build kit** | Turn a visual idea into usable colors, dimensions, materials, references, and exportable maker/design files. |
| 9 | **Visual time machine** | Revisit what you were collecting and why at a given time; surface forgotten threads and changed taste. |
| 10 | **Material lab** | Compare saved surfaces under different lighting and pair them with real material samples when available. |
| 11 | **Critique on the object** | Collaborators mark an exact region of an image or model and discuss a decision while the rest of the library stays private. |
| 12 | **Board to moving story** | Turn selected images into a timed visual sequence with transitions, captions, and natural voice if narration is wanted. |

**Best first bet:** Go to 3D is closest to the existing select-and-board flow and has a clear result to judge. **Best companion bet:** Point and reopen would make saved images useful when the person is away from the desk. Both need real user testing before claims about demand or quality.
